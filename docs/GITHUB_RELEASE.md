# คำแนะนำการดูแลและการเผยแพร่เวอร์ชันบน GitHub

หากคุณ Fork หรือ Clone คลังโค้ดนี้ไปแก้ไขปรับแต่งเอง เมื่อจะเผยแพร่เวอร์ชันใหม่โปรดระวังประเด็นต่อไปนี้:

## 1. ห้าม Commit ไฟล์ที่เป็นความลับขึ้นคลังโค้ดเด็ดขาด

ก่อนทำการ Commit ให้ใช้คำสั่ง `git status` ตรวจสอบให้แน่ใจว่ารายการต่อไปนี้**จะไม่ถูกส่งเข้า Git อย่างแน่นอน**:
- `.env` และไฟล์คอนฟิกสำรองทั้งหมด
- โฟลเดอร์ `data/` (รวมถึงฐานข้อมูล SQLite และไฟล์สื่อที่บันทึกไว้ในเครื่อง)
- ไฟล์ Google OAuth Client JSON, โทเค็น หรือล็อกต่างๆ

## 2. การซิงค์หมายเลขเวอร์ชัน

เมื่ออัปเดตเวอร์ชัน แนะนำให้แก้ไขหมายเลขเวอร์ชันในไฟล์ต่อไปนี้ให้ตรงกัน:
- `api/app/__init__.py`
- `pyproject.toml`
- `docker-compose.yml`
- `web/package.json`

โปรดแยกแยะระหว่าง **หมายเลขเวอร์ชันของโปรแกรม** (เช่น `0.1.28`) กับ **หมายเลขเวอร์ชันของเทมเพลตเวิร์กโฟลว์แต่ละตัว** (เช่น H3 ref2v เวอร์ชัน `1.4.0`) เพื่อป้องกันความสับสน

## 3. คำสั่งตรวจสอบในเครื่องก่อน Push

ก่อน Push แนะนำให้รันคำสั่งทดสอบและบิลด์ให้ผ่านทั้งหมด:

```bash
uv run pytest -q
uv run ruff check api tests
npm --prefix web run test:contract
npm --prefix web run build
git diff --check
```
