# ขั้นตอนการตรวจสอบโมเดลจริง การทดสอบ Smoke Test และการเผยแพร่

เพื่อป้องกันไม่ให้เวิร์กโฟลว์ที่ยังไม่ผ่านการทดสอบหรือโหนดที่ไม่ทราบที่มาเปิดใช้งาน GPU แล้วเสียค่าใช้จ่ายโดยเปล่าประโยชน์ ระบบจึงกำหนดให้โมเดลจริงและเวิร์กโฟลว์ทั้งหมดต้องผ่านกระบวนการ 4 ขั้นตอน: **"ตรวจสอบ (Review) → ทดสอบจริง (Real Smoke) → ตรวจรับ (Accept) → เผยแพร่ (Publish)"** จึงจะสามารถใช้งานในหน้าสร้างสรรค์ได้อย่างเป็นทางการ

ด้านล่างนี้คือลำดับการเรียก Administrator API (ทุก endpoint จำเป็นต้องเข้าสู่ระบบในฐานะผู้ดูแลระบบ):

## 1. ตรวจสอบโมเดล (Review Model)

เมื่อตรวจสอบแหล่งที่มาของคลังโมเดล, หมายเลข commit hash 40 หลัก, สัญญาอนุญาต และความต้องการของฮาร์ดแวร์ถูกต้องเรียบร้อยแล้ว ให้เรียกคำสั่ง:

```http
POST /api/gpu/models/{model-row-id}/review
Content-Type: application/json

{"confirmed": true, "license_accepted": true}
```

> `{model-row-id}` ในที่นี้คือ `id` ของรายการที่ได้รับจาก `GET /api/gpu/models` ขั้นตอนนี้เป็นเพียงการบันทึกว่า "ตรวจสอบแล้ว" และยังไม่ได้ตั้งค่าเปิดใช้งานโมเดล

## 2. ตรวจสอบเวิร์กโฟลว์ (Review Workflow)

ให้กดปุ่ม **ตรวจสอบ (Validate)** ในหน้า "เวิร์กโฟลว์" บนเว็บก่อน (หรือเรียก `POST /api/gpu/workflows/{workflow-id}/validate`) จากนั้นเรียกคำสั่ง:

```http
POST /api/gpu/workflows/{workflow-id}/review
Content-Type: application/json

{"confirmed": true}
```

ระบบหลังบ้านจะตรวจสอบโดยอัตโนมัติ:
- `comfyui_commit` เป็น commit hash 40 หลักที่กำหนดตายตัวหรือไม่
- `custom_nodes` เป็นค่าว่าง หรืออยู่ในไวต์ลิสต์ที่ผ่านการตรวจสอบใน `runtime_worker.py` หรือไม่
- น้ำหนักโมเดลทั้งหมดใน `weight_files` มีการระบุคลัง Hugging Face, revision 40 หลัก และค่าแฮช SHA-256 64 หลักครบถ้วนหรือไม่
- โหนดกราฟมีโหนดที่เป็นอันตรายหรือไม่

## 3. รันการทดสอบความพร้อมบน GPU จริงแบบจำกัดงบประมาณ (`real-smoke`)

เมื่อผ่านการตรวจสอบแล้ว ให้เริ่มการทดสอบบนเครื่องจริงขนาดเล็ก (จำกัดเวลาสูงสุดไม่เกิน 5 นาที):

```http
POST /api/gpu/workflows/{workflow-id}/real-smoke
Idempotency-Key: smoke-คีย์สุ่มเฉพาะของคุณ
Content-Type: application/json

{
  "confirmed": true,
  "project_id": "รหัสโปรเจกต์ของคุณ",
  "params": {"prompt": "test"},
  "asset_ids": [],
  "spec": {"key": {"variant": "GPU", "accelerator": "T4", "shape": "STANDARD"}}
}
```

> หากเป็นเวิร์กโฟลว์แปลงภาพเป็นวิดีโอหรือใช้ภาพอ้างอิง อย่าลืมอัปโหลดภาพอ้างอิงไปยังโปรเจกต์นั้น และส่งรหัสไฟล์ที่เกี่ยวข้องใน `params` / `asset_ids` และปรับการ์ดจอ `accelerator` เป็น `"L4"` หรือสเปกที่บัญชีของคุณรองรับ

หลังจากส่งงาน Worker จะเริ่มแคชสภาพแวดล้อมและโมเดลไปยัง Google Drive ผ่าน CPU runtime ก่อน (หากยังไม่เคยแคช) จากนั้นจึงเปิด GPU เพื่อประมวลผลจนได้ผลงาน และสุดท้ายจะลบ runtime ทิ้งโดยอัตโนมัติ

## 4. ตรวจรับผลการทดสอบและเปิดใช้งานโมเดล (`accept-smoke`)

เมื่องานทดสอบข้างต้นมีสถานะเป็น `completed` และสัญญาเช่า runtime ที่เกี่ยวข้องเปลี่ยนเป็น `deleted` แล้ว ให้เรียก endpoint ตรวจรับ:

```http
POST /api/gpu/workflows/{workflow-id}/accept-smoke
Content-Type: application/json

{"job_id": "รหัสงานทดสอบที่รันเสร็จแล้ว", "confirmed": true}
```

เมื่อระบบหลังบ้านตรวจสอบค่าแฮชของผลงานและบันทึกการวินิจฉัยของ GPU ถูกต้องแล้ว จะทำเครื่องหมายเวิร์กโฟลว์นี้เป็น `smoke_test_passed=true` และปรับสถานะโมเดลที่เกี่ยวข้องเป็น **`enabled=true`** อย่างเป็นทางการ

## 5. เผยแพร่เวิร์กโฟลว์อย่างเป็นทางการ

ขั้นตอนสุดท้าย ในหน้า "เวิร์กโฟลว์" บนเว็บ ให้คลิกปุ่ม **ยืนยันการเผยแพร่** (หรือเรียก `POST /api/gpu/workflows/{workflow-id}/publish` พร้อมส่ง `{"confirmed": true}`)

เมื่อเผยแพร่เสร็จสมบูรณ์ เวอร์ชันนี้จะกลายเป็นเวอร์ชันเริ่มต้น และพร้อมให้เรียกใช้งานบนมือถือในหน้า "สร้างสรรค์" ได้ทันที!
